# Changelog

## Unreleased

- **Core engine** (`src/core`, no Payload, no React): `layout(template, data, media, context)` returns positioned marks in millimeters with warnings; field tokens with dotted paths (up to 4 segments) and the formatters `date`, `money`, `upper`, `lower`, `default` and `slice`, parsed without `eval`; text fitting by shrink, ellipsis or wrap; barcode value checks; sheet grid positions from a start slot; the 4 x 6 inch thermal preset.
- **Provider contract** (`src/contracts/labels.ts`, types only): templates, sets and tokens that other plugins can offer.
- **Plugin**: `labelsPlugin()` adds `label-templates`, `label-media` and `label-prints`. Writes are refused unless the site grants them with an `access` check that returns exactly `true`. Options `scopeField` with `scopeCollection` and `scopeOf`, and `log`. With a scope field, reads, creates, updates and deletes are limited to the person's own scope (records with no scope are readable by all, and changed only by a platform admin); no scope means no access.

- **Outputs**: `renderSvg` (core) and `renderPdf` (`./pdf` export, pdfkit), one label per page, from the same marks. Barcodes, QR and Data Matrix are drawn as vectors with bwip-js; a value that can't be encoded draws a dashed box and the layout already warns. New dependencies: pdfkit and bwip-js (both MIT).

- **Print endpoint** `POST /api/labels/print` (`template`, `ids`, `copies`): a PDF, one label per page. Refuses with a plain message when signed out, without the print right, without a scope, for another scope's template, for any document the person cannot read, and over 2,000 labels. Writes one print-log entry (ids and counts only) server-side.

- **Fail closed.** The plugin throws at config time unless `access.manage` or `access.print` is set. `access.print` decides printing; without it only `access.manage` may print. Templates and media are read by whoever may manage or print (a printer must read the template); the log is read by `manage` only. There is no signed-in fallback. The template lookup tries the key, then the id exactly as given, so numeric ids work on Postgres and SQLite.

- **Sheet media.** `renderPdf(labels, media, start)` places labels on Letter pages in the media's grid from a start slot and flows onto new pages. Presets `avery-5160` (3 x 10) and `avery-5163` (2 x 5). `parseMedia` checks stored media records. The print endpoint takes `media` (a preset key, or a stored media by key or id; default is the template's own media, else 4 x 6 in thermal) and `start` (1-based, sheets only). It refuses an unknown or broken media, another site's media, a start slot out of range, and a template larger than the sheet's labels, each with a plain message and nothing logged. Media records get an optional `key`. Sets are not built.
  - Tested: slot math, page size in points (612 x 792), page counts with and without a start slot, endpoint refusals and happy paths on in-memory MongoDB.
  - Not tested: Avery measurements against a printed sheet (taken from published sizes), printing at 100% on a real printer, sets.

- **Sets.** A `label-sets` collection (same scope and access rules as templates) holds named lists of steps. A step names a template and reaches its records `self`, `forward` (a relationship field path, up to 4 fields) or `backward` (records in a collection whose field points at the current one), and may start from an earlier step (`from`) so steps chain. The print endpoint takes `set` and a starting `id` and prints all of the set's labels in one PDF with one log entry (`label-prints` gets a `set` field). Every record is read as the person; a missing or unreadable record, a template on another site, or another site's set refuses the whole run; a backward step compares what the person may read with the real count and refuses if records are hidden. The 2,000-label cap counts the whole set, copies included. The design's tube example is corrected: tubes carry the manufacturer's label, and our labels go on the kit bag, kit box, shipping box and lab batch.
  - Tested: 8 tests on in-memory MongoDB with two made-up sites: chained self, backward and forward steps, copies, the cap, cross-site refusal for a set, a template and a record, an unreadable record (hidden kit, and a batch on another site) refusing the run with no log entry, a template on the wrong collection, and the set collection refusing a non-manager and the other site.
  - Not tested: a polymorphic relationship in a backward step (not supported), many thousands of records in a step, rendering time, a real kits plugin, SQL databases, a set run from the admin (no dialog yet).
- **Media bounds (review).** Stored media is refused when a page or roll is over 1,000 mm on a side or a sheet has more than 1,000 labels per page. Tested: 1 new test. Not tested: the dialog with a large legal sheet.

No version bump (still 0.0.0).

Tested: 44 tests with made-up data. Core math and tokens; PDF page count and size (288 x 432 pt for 4 x 6 in), SVG viewBox, text escaping, rotation, vector barcodes, invalid barcode without a crash; the print endpoint on in-memory MongoDB (page count, one log entry with ids only, 2,001-over refusal with count, signed-out, no scope, other site's template, an unreadable record, bad requests); config throws with neither access option, manage-only and print-only behavior, and the template lookup order with a stand-in for Payload; a Payload config build checking the collections, default access and strict answers; and an in-memory MongoDB run with two sites proving cross-scope reads, creates, updates, deletes and moves are refused, the shared template is admin-only, the print log is unwritable, and signed-out and scope-less users get nothing.
Not tested: the cost of reading printed documents at depth 3 (to revisit before 0.1), numeric ids on a real SQL database, the endpoint over real HTTP, 2,000 labels' render time (the 2,000 limit is a guess), PDF in a viewer or printer, SVG in a browser, scanning a printed barcode, sheet pages, images in output, real font metrics,  real printers.
